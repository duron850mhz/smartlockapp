# スマートロック管理アプリ

Sesame（CandyHouse）のWeb APIを使って、複数のスマートロックの状態確認・施錠/解錠を行うPWAです。

## 概要

- ロック一覧をカードで表示（施錠中=赤 / 解錠中=青のダイヤルで状態を表示）
- タップで施錠・解錠
- UUID・シークレットキーはロックごと、APIキーは全ロック共通で登録
- UUID・シークレットキー・APIキーは**すべてこの端末のブラウザ内（localStorage）にのみ保存**。サーバーには一切送信しない
- PWA対応（ホーム画面に追加可能、Service Workerでオフラインキャッシュ）

## 技術構成

- React + Vite
- Tailwind CSS
- vite-plugin-pwa（Service Worker / マニフェスト生成）
- aes-js（Sesame Web APIの署名に必要なAES-CMACをブラウザ上で計算するために使用）

npm install

```bash
npm run dev
```

## ビルド

```bash
npm run build
```

`dist/` フォルダが生成されるので、この中身をWebサーバーの公開ディレクトリに置く。

- `src/` や `package.json` などのソース一式はサーバーに置く必要はない（`dist/` の中身だけでよい）
- `vite.config.js` で `base: "./"` を設定済みなので、ドメイン直下ではなく1つ下のサブフォルダ（例: `/smartlock/`）に置いてもそのまま動く

### Apacheでの配置例

```bash
npm run build
cp -r dist/* /var/www/html/smartlock/
```

## 初期設定（アプリ側）

1. 右上の歯車アイコンから設定画面を開く
2. 「APIキー（全ロック共通）」を入力
3. 「ロックを追加」から、ロックごとに 名前 / UUID / シークレットキー を登録
4. 必要なら「起動時に自動でステータスを更新する」にチェック（後述）

いずれもCandyHouseのSesame Web API（`https://document.candyhouse.co/demo/webapi-ja`）から取得したもの。

## API呼び出しについての方針

無料枠は1000リクエスト/月（アカウント全体でロック台数分を共有するプール）で、今後さらに減る可能性がある前提のため、なるべく呼び出し回数を抑える設計にしている。

- **バックグラウンドでの自動ポーリングは行わない**（`setInterval`やService Workerの定期同期は未実装、意図的）
- アプリ起動時の挙動は設定画面の「起動時に自動でステータスを更新する」チェックボックスで選択可能
  - OFF（デフォルト）: localStorageにキャッシュされた前回取得の状態を表示するだけで、APIは叩かない
  - ON: 起動直後に1回だけ、登録済みロック台数分のステータス取得APIを叩く（外出先で解錠したまま手動施錠した場合など、アプリ側の表示とズレるのを防ぎたい人向け。その分、枠の消費は早くなる）
- ステータス取得は上記の起動時更新に加え、**右上の更新ボタンを押した時**にも行える
- 施錠/解錠コマンド送信後は、成功したら**楽観的にUI上の状態を即切り替え**、実際に動いたかどうかの確認GETは自動では行わない（心配なときは手動で更新ボタンを押す運用）

## 既知の注意点・未検証事項

- `/cmd` のPOSTはHTTP 200が返っても「コマンドを受け付けた」ことの確認であり、物理的にロックが動いたことまでは保証されない（電波状況等で動かないケースが報告されている）
- ブラウザから `app.candyhouse.co` への直接fetchがCORSで弾かれないかは未検証。弾かれる場合はプロキシ経由での呼び出しに変更が必要
- Service Workerの自動更新（`registerType: "autoUpdate"`）は、次にアプリを開き直したタイミングで新バージョンを検知し、確認なしで自動リロードする設定。デプロイ直後に即座に切り替わるわけではない
- Service Workerの登録自体、HTTPS（またはlocalhost）でないと機能しない。HTTP配信の場合、通常のWebアプリとしての表示・操作は問題ないが、PWAとしてのオフライン機能やホーム画面追加は動作しない可能性がある
